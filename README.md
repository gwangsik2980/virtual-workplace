# VIRTUAL WORKPLACE

가상의 식품 제조기업이 매일 운영되고, 가상의 구매 담당자가 실제에 가까운 구매 업무를 처리합니다.
사용자는 그 과정을 관찰하며 구매 직무를 배우고, 업무의 비효율을 찾아 개선 도구를 만들어 업무에 적용하고, 효과를 검증합니다.

- 배포 주소: https://gwangsik2980.github.io/virtual-workplace/
- 기획서: `docs/PLAN_MAPPING.md`에 기획서 항목별 구현 위치를 정리했습니다.

> 회사(가온식품), 인물, 공급업체, 시세는 모두 가상 데이터입니다. 실제 기업·시장과 무관합니다.

## 핵심 순환

```
가상 기업 운영 → 직원 업무 수행 → 사용자 관찰·학습 → 문제 발견
→ 도구 개발 → 업무 적용 → 성과 검증 → 기업·직원 변화 → 다음 업무
```

## 무엇이 구현되어 있나

| 영역 | 내용 |
|---|---|
| 기업 | 식품 제조기업 1곳. 생산·재고·현금·매출채권·매입채무가 매일 움직임 |
| 구매 업무 | 구매요청 → 시장조사 → 원가분석 → 견적요청 → 견적 비교 → 협상 → 품의 → 발주 → 입고 → 검수·정산 |
| 직원 | 구매 담당자 1명. 업무를 할수록 숙련도와 경험치가 쌓이고 승진함 |
| 연속성 | 브라우저 자동 저장 + JSON 내보내기·불러오기. 저장 후 이어 진행해도 결과가 같음(테스트로 확인) |
| AI Tool Lab | 견적서 정보 추출·비교표 자동 생성 도구 v1.0, v1.1, 월간 구매 실적 보고서 초안 생성 도구 v1.0, 납기 위험 알림 도구 v1.0. 업무에 직접 연결됨 |
| 효과 검증 | 같은 상태에서 "도구 없음 / 도구 적용" 두 세계를 같은 기간 돌려 비교 |
| 학습 | 업무를 처음 관찰할 때 열리는 구매 개념 카드 18장, 관찰 메모, 개선 과제 보드 |

## 도구 효과를 어떻게 측정하나 (중요)

정해 둔 "개선율"을 곱하지 않습니다. 대신 이렇게 계산합니다.

1. 수작업 경로에서 담당자는 견적서 필드를 하나씩 입력하고, 필드마다 일정 확률로 오입력이 생깁니다. 업체마다 양식이 달라서(USD, 포대 단위, VAT 포함, 스캔본) 환산 실수도 생깁니다.
2. 담당자는 틀린 줄 모르고 **입력값**으로 업체를 고르고 발주서를 씁니다.
3. 비용은 **실제 값**으로 계산합니다. 잘못된 선택은 손실로, 발주서 단가 오류는 정산 불일치와 재작업 시간으로 나타납니다.
4. 도구는 견적서 원문을 실제로 파싱합니다. 파싱이나 검증에 실패한 필드는 사람이 직접 입력합니다.

시간·오류율 같은 기본값은 실측 자료가 없는 **가정치**입니다. 앱의 "가정·설정" 화면과 `docs/ASSUMPTIONS.md`에 근거 수준을 밝혀 두었고, 값을 바꿔 결과가 어떻게 달라지는지 확인할 수 있습니다.

## 실행

```bash
npm install
npm run dev      # 개발 서버
npm test         # 시뮬레이션·도구 테스트
npm run build    # 배포용 빌드 (dist/)
```

`main` 브랜치에 푸시하면 GitHub Actions가 테스트 → 빌드 → GitHub Pages 배포를 진행합니다.
처음 한 번은 저장소 Settings → Pages → Source를 **GitHub Actions**로 바꿔야 합니다.

## 기술 구성

- React 18 + TypeScript + Vite, 테스트는 Vitest
- 서버·유료 API 없음. 모든 시뮬레이션이 브라우저에서 돌아갑니다
- 차트는 의존성 없이 SVG로 직접 그립니다

```
src/
  sim/        시뮬레이션 엔진 (UI와 독립, 순수 TypeScript)
  tools/      도구 슬롯 규격과 도구 구현
  ui/         화면
tests/        시뮬레이션·도구 테스트
docs/         기획 대응표, 가정, 도구 개발 안내, 구매 프로세스 정리
```
