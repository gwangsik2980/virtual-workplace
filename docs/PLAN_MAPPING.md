# 기획서 대응표

기획서(VIRTUAL WORKPLACE 기획 보고서, 2026-11-02 초기 기획 정리본)의 항목이 어디에 구현되었는지 정리합니다.

## 기획 원칙

| 원칙 | 구현 |
|---|---|
| 기업 전체를 하나의 플랫폼으로 | `src/sim/operations.ts` 생산·재무·물류·품질 연동, 기업 현황 화면의 부서 카드와 자재 흐름 |
| 초기 범위는 구매에 집중 | 구매 업무 12단계 (`src/sim/purchasing.ts`) |
| 사용자가 구매를 안다고 가정하지 않음 | 관찰 시 열리는 개념 카드 (`src/sim/learning.ts`), 관찰자 모드로 오입력 확인 |
| 실제 프로세스 기반 업무 설계 | `docs/purchasing-process.md` (일반 지식 기반, 출처 미검증) |
| 도구를 실제 업무에 연결 | 도구 슬롯 (`src/tools/types.ts`), 견적 비교 단계에서 엔진이 도구 호출 |
| 다음 세션에도 이어서 진행 | 자동 저장 + JSON 내보내기·불러오기 (`src/sim/persistence.ts`), 테스트로 연속성 확인 |

## 연속성 설계 (4장)

| 항목 | 구현 |
|---|---|
| 재고·현금·예산·거래처가 다음 기간으로 | `GameState` 전체 저장 |
| 직원 경력·역량 누적 | `src/sim/employee.ts` 숙련도·경험치·승진·이정표 |
| 미완료 업무가 남음 | 구매 건 단계·남은 작업 시간 저장 |
| 이전 결정이 다음에 영향 | 업체 실적(불량·납기)이 다음 견적 비교 점수에 반영 |
| 상태 기반 업무 발생 | 재고가 재주문점 아래로 내려가면 구매 요청, 판촉으로 사용량 증가 |
| 학습 기록·개선 과제·도구 버전 | `LearningState`, `AppliedTool`, `VerificationRun` |

## 구매 성과 (5장)

- 대표 KPI: 가격 절감액 = (선정 업체의 협상 전 최초 견적 − 최종 단가) × 입고 수량
- 시장 변동분은 `marketMoveKRW`로 따로 기록해 구매 활동 성과와 분리
- 운영 성과: 납기 준수율, 불량률, 결품일수 함께 표시

## AI 업무 개선 연구소 (6장)

- 견적 비교 도구 v1.0, v1.1 구현 (`src/tools/quoteCompare/`)
- 원본 대조: 추출값마다 원문 근거 문자열 보관
- 검증 규칙: 시장가 ±40%, 납기 1~60일, 결제 0~120일
- 사람 승인: 업체 선정은 담당자, 발주는 팀장 승인 후
- 실패 시 수작업 복귀: 추출·검증 실패 필드는 사람이 입력
- 가상 데이터로 시작

## 개발 단계 (8장)

| 단계 | 상태 |
|---|---|
| 0. 실무 기반 조사 | 일반 지식으로 정리한 뒤 공개 자료와 대조함 (`docs/practice-sources.md`, 18개 개념 중 7개 보완). 검색 요약 기준이라 원문 대조와 실무자 검증이 남음 |
| 1. 기업 기반 | 완료 |
| 2. 구매 업무 | 완료 |
| 3. 지속 운영 | 완료 (일 단위 수동 진행, 규칙 기반 사건) |
| 4. AI Tool Lab | 견적 비교, 월간 보고서 초안, 납기 위험 알림 도구 완료 |
| 5. 성과 검증 | 반사실 비교 완료 |
| 6. 확장 | 보류. 구매가 안정된 뒤 진행. 도구 슬롯과 부서 구조는 확장 가능하게 설계 |
