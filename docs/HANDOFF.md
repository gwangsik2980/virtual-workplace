## 회사 공유와 닫아 둔 동안 알림 (2026-11-03 밤 배포)

**사용자가 원하는 것**
1. 폰(홈 화면 앱)과 PC 웹이 **같은 회사**를 본다. 지금은 브라우저마다 저장이 따로라 다르다.
2. 사이트를 닫아 두어도 폰으로 알림 7종(결품, 긴급, 지연, 품질, 정산, 납기 위험, 급여)이 온다.
3. 다른 사람(포트폴리오 방문자)이 내 회사를 바꾸지 못한다.

**설계 (사용자 승인, C안 "관리자 키")**
- 연결 코드·기기 그룹 방식은 사용자가 번거롭다고 해서 버렸다. 서버에 회사 하나(Durable Object 이름 `main`).
- 보기: 누구나. 사이트를 열 때, 1분마다, 화면으로 돌아올 때 `GET /state?since=rev`로 새 저장본을 받아 바꾼다(`replace(next, { remote: true })`). 방문자가 누른 것은 그 브라우저에만 남는다.
- 바꾸기·알림: 관리자 키(20자리, I·L·O·U 뺀 32글자)를 넣은 기기만. 사용자 조작(store `userRev`: update, replace, reset, undo, 수동 advance)이 있으면 1.5초 모아 `POST /state`(gzip+base64, 1년치 약 100KB). 마지막에 올린 쪽이 이긴다. 실시간 따라잡기는 올리지 않는다(재현성 원칙으로 어디서나 같은 결과).
- 키: 메뉴 하단 회색 글씨 "관리자 키". 서버에 주인이 없을 때만 "이 기기 회사로 키 만들기"가 보인다(`POST /claim`, 처음 한 번만, 서버에는 SHA-256 해시만). 다른 기기는 키를 붙여넣는다(`POST /check`로 확인 후 서버 회사로 바뀜). 아이폰 홈 화면 앱은 Safari와 저장소가 달라 직접 붙여넣어야 한다.
- 알림: 키가 있는 기기가 예정표를 계산해 `POST /schedule`. 알림 켜기(알림 종 → "닫아 둔 동안에도 받기", 키 있는 기기에서만 보임) → `/subscribe`(구독 + 이 기기의 알림 종류) → `/test`. 서버가 시각이 되면 구독 기기마다 켠 종류만 보낸다. 켜져 있으면 화면 쪽 팝업은 보내지 않는다.
- 비용: Cloudflare 무료 요금제는 한도를 넘으면 오류가 날 뿐 과금되지 않는다(요금 문서 원문 확인). 유료(월 5달러)로 바꾸지 말 것.
- 서버 수정: `worker/` 코드를 고쳐 main에 올리면 `.github/workflows/push-worker.yml`이 자동 배포한다(**main 푸시 때만**). 재배포해도 Durable Object에 저장된 회사·예정표·키는 남는다.

**끝난 것**
- `worker/src/webpush.ts`: RFC 8291 암호화와 VAPID 서명. RFC 부록 A 예시와 바이트 단위로 같고, 애플 푸시 서버에서 서명 통과 확인.
- `worker/src/box.ts`, `index.ts`: 경로 `GET /key|/owner|/state?since=`, `POST /claim`, 키 필요 `POST /check|/state|/schedule|/subscribe|/unsubscribe|/test`(헤더 `Authorization: Bearer 키`). 테스트 `tests/pushBox.test.ts`.
- `src/ui/sync.ts`(받기·올리기·키), `src/ui/server.ts`(서버 주소 `VITE_SERVER`, 비어 있으면 기능 숨김), `src/ui/push.ts`, `src/ui/components/OwnerKey.tsx`. 테스트 `tests/sync.test.ts`.
- `src/ui/realtime.tsx`: 따라잡기 중복 방지를 상태 객체 기준으로 바꿈. 예전에는 시드·날짜가 같으면(처음부터 다시 시작, 받은 저장본) 따라잡기가 안 돌았다.
- 로컬 확인(wrangler dev + 브라우저 4개): 키 만들기 → 새 방문자가 열면 같은 회사 → 틀린 키는 "키가 맞지 않아요" → 방문자가 파일을 불러와도 서버 회사 그대로 → 폰에 키 입력 → 폰에서 바꾸면 PC와 방문자도 바뀜. 1440·390px, 라이트·다크 확인.

- **렉**: 가만히 있어도 화면을 초당 60번 이상 다시 칠하고 있었다. 원인 둘. (1) 상태 불 깜빡임이 `box-shadow`를 무한 반복해 매 프레임 다시 칠함 → 고리를 따로 두고 `transform`·`opacity`로만 움직이게 바꿈. (2) Lenis가 `requestAnimationFrame`을 쉬지 않고 돌림 → 처음엔 뺐는데 사용자가 "부드러운 느낌이 없어졌다"고 해서 되살리고, 휠·키·터치 입력 때만 루프를 돌리고 멈추면 끄게 바꿈(다시 켤 때 Lenis 내부 시계 `time`을 지금으로 맞춰야 첫 프레임에 끝까지 뛰지 않는다). (3) 스크롤과 함께 움직이는 카드 5곳의 `backdrop-filter` 블러를 뺌(빼도 화면 차이는 픽셀 0.5% 정도, 대부분 초 단위 시계). 4배 CPU 감속에서도 스크롤은 60fps였으니 남은 버벅임은 GPU 쪽으로 봤다. `.reveal`은 나온 뒤 `will-change`를 놓는다. Playwright 추적(1440px, 근무 중, 첫 화면) 가만히 3초: Paint 546회 → 6회, 휠 3초: Paint 918회 → 33회.
- **메신저**: 같은 날 구매 요청 여러 건을 건마다 '요청 → 답'으로 몇 분 사이에 다섯 번씩 주고받던 것을, 생산팀이 한 메시지에 목록(긴급/일반)으로 보내고 GWANG이 한 번에 답하게 바꿨다(`purchasing.ts` `requestChats`). 긴급이 여럿이면 팀장도 한 번만 묻는다. 결품이 며칠 이어지면 같은 말을 되풀이하지 않고 "오늘도/n일째"로 묻고, GWANG은 실제 발주의 약속 입고일로 답한다. 팀장 경위 지시는 첫날만(`operations.ts` `stockoutChat`). 이미 쌓인 예전 대화는 그대로이고, 새로 계산되는 날부터 바뀐다.

- **원인 확인과 가벼운 모드**: 사용자 노트북 `chrome://gpu`가 "Compositing: Software only. Hardware acceleration disabled"였다(크롬 그래픽 가속 꺼짐). 사용자가 켰다. 같은 방문자를 위해 가벼운 모드를 만들었다(`src/ui/lite.ts`, `main.tsx`에서 첫 화면 전에 `html.lite`). 등장 효과·인트로 로더·Lenis·불 깜빡임·헤더/드로어 흐림을 끄고 숫자 올라가기도 최종값으로. 관리자 키는 렉과 무관(키 없이도 1분마다 짧은 확인 요청만).

- **뒤로가기** (`src/ui/history.ts`): 화면 전환이 방문 기록에 안 남아 뒤로가기 한 번에 사이트를 떠났다. 이제 화면을 바꾸면 기록을 쌓고 주소에 `#desk`처럼 붙는다(주소로 바로 그 화면을 열 수 있다). 구매 건 드로어와 메뉴는 열려 있는 동안 기록을 하나 쌓아 뒤로가기로 닫히고, 버튼으로 닫으면 그 기록을 되돌린다. 메뉴·드로어 안에서 화면을 고르면 창 기록을 새 화면으로 바꿔 쓴다. Playwright로 화면→뒤로, 드로어·메뉴→뒤로, 메뉴→화면 두 번→뒤로·앞으로, 마지막 뒤로에 사이트 이탈까지 확인.

- **화면 손질 (사용자 요청)**: 직원 업무 순서를 하루 일정 → 진행 중 업무 → 숙련도 → 급여와 통장 → 경력 기록으로. 첫 화면 '지금' 패널: 진행 중인 구매 카드는 넓은 화면에서 왼쪽 '지금' 카드 높이에 맞추고(`contain: size`) 넘치면 스크롤, '외 n건 더 보기' 대신 전부 목록에, 아래에 더 있으면 맨 아래를 흐리게(끝까지 내리면 사라짐, 사용자가 A안 선택). 두 카드 아래 폭 전체에 얇은 하루 일정 줄(`components/DayBar.tsx`, 직원 업무와 같은 부품, `compact`). 주소창에서 `#desk`처럼 고쳐도 그 화면으로 간다.

- **업무 일지** (`components/WorkLog.tsx`): 근무 중이 아닐 때 '지금' 카드에 "금일 업무 일지 보기"(퇴근 뒤) 또는 "11/3 업무 일지 보기"(출근 전·휴일, 마지막 근무일). 누르면 보고서 형식 창: 일자·작성자·근무 시간·실근무 머리표, 1 업무 요약, 2 시간대별 내역(점심 전후 "(계속)"은 한 줄, 소요에는 점심 제외), 3 구매 건 진행(그날 첫 단계 → 마지막 단계), 4 주요 사항(그날 사건), 5 다음 영업일로 넘어가는 일. 줄을 누르면 구매 건이 열린다. 첫 화면 등장 효과 상자 안에서는 헤더 아래 깔려서 `createPortal`로 body에 그린다. 뒤로가기·Esc로 닫힌다.

## 사용자 선호 (작업 방식)

- 한국어로 답한다. 소제목과 줄바꿈으로 나누고, 이유와 근거를 함께 쓴다.
- 수치에는 출처를 남기고, 추정이면 추정이라고 밝힌다. "원문 확인"과 "검색 요약"을 구분한다.
- 부족한 점은 돌려 말하지 않고 짚는다. 하지만 비중이 작은 일(예: 공휴일)에 보고를 길게 하지 않는다.
- 포트폴리오 글은 사용자가 요청할 때만 고친다. 기능 작업 끝에 "포트폴리오에 반영할까요"라고 묻지 않는다.
- 사용자에게 경험을 물을 때는 번호 매긴 구체적인 질문을 먼저 한다.
- 과하게 큰 UI 요소를 싫어한다. 화면을 바꾸면 Playwright로 1440px·390px, 라이트·다크를 찍어 확인한다.
- 링크 페이지(`gwangsik2980.github.io/links/`) 같은 다른 공개 페이지를 바꿀 때는 먼저 확인받는다.
- 앱 안에서는 실제 기업명을 쓰지 않는다. 실제 기업과 비슷한 이름은 앞뒤를 바꾼다 (예: 대한제분유통 → 제분대한유통).

## 화면 확인 요령

- 데이터가 쌓인 상태: Vitest로 `createInitialState(seed, '2026-11-03', 'realtime')` 후 `advanceDays`를 돌려 JSON으로 저장한다.
- Playwright에서 저장 파일은 **`context.addInitScript`로 페이지가 뜨기 전에** localStorage `virtual-workplace/save/v1`에 넣는다. 페이지를 연 뒤 `evaluate`로 넣고 새로고침하면, 실시간 따라잡기가 새 회사를 저장하면서 덮어쓸 때가 있다.
- 근무 중 화면을 보려면 `newContext({ timezoneId: 'Asia/Seoul' })`. 컨테이너 시계는 UTC다.
- 테마는 localStorage `virtual-workplace/theme`(`light`/`dark`), 첫 화면은 `virtual-workplace/screen`(`chat`, `desk` 등).
- `npm run build` 후 `npx vite preview --port 4173`, 주소 `http://localhost:4173/virtual-workplace/`. 서버를 끌 때는 `lsof -t -i:4173 | xargs kill` (`pkill -f`는 자기 셸까지 죽인다).
- 헤더 nav는 화면 폭 1880px 이상에서만 보인다. 메뉴 항목은 `.navmenu-item`으로 찾는다 (`getByText`는 숨은 헤더 버튼을 먼저 잡는다).

## 환경 메모 (클라우드 세션)

- 네트워크 설정을 사용자가 넓혀서 curl과 Playwright로 외부 사이트(law.go.kr, astro.kasi.re.kr 등)를 열 수 있다. WebFetch 도구는 DNS 오류가 나서 curl이나 브라우저를 쓴다. 자바스크립트로 본문을 불러오는 법령 페이지는 Playwright로 열어 `innerText`를 읽는다.
